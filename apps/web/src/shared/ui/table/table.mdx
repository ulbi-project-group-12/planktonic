# Table

Универсальный атом таблицы. `Table` рендерит сетку колонок, `TableRow` — строку на той же сетке.
Весь функционал опционален: таблица может быть просто информационной, а может поддерживать
сортировку, выбор строк и меню действий одновременно.

- Стили — только по токенам дизайн-системы; светлая и тёмная темы переключаются классом `dark` на контейнере.
- Составляющие (чекбоксы, меню, скелетоны) — атомы из `shared/ui`, внутри не дублируются.
- Живые примеры ниже кликабельны: сортировка, выбор и меню работают.
- Все состояния в обеих темах — в истории **States**, интерактивные переключатели — в **Playground**.

## Быстрый старт

```tsx
import { Table } from '@/shared/ui';
import type { TableColumn } from '@/shared/ui';

interface Task {
  id: string;
  title: string;
  due: string;
}

const columns: TableColumn<Task>[] = [
  { id: 'id', header: 'ID', accessor: (task) => task.id, sortable: true, width: 90 },
  { id: 'title', header: 'Задача', accessor: (task) => task.title, sortable: true },
  { id: 'due', header: 'Срок', accessor: (task) => task.due, sortable: true, sortType: 'date' },
];

<Table<Task> data={tasks} columns={columns} rowKey={(task) => task.id} caption="Задачи проекта" />;
```

- `data` — массив строк любой формы; компонент обобщённый (`Table<Task>`).
- `columns` — описание колонок (см. справочник ниже).
- `rowKey` — уникальный ключ строки. Нужен для выбора; без выбора можно вернуть индекс, но стабильный id предпочтительнее.
- `caption` — доступное имя таблицы для скринридеров. Обязательно, если на странице может быть вторая таблица.

## Кейс: просто данные

Минимальная информационная таблица: без чекбоксов, сортировки и действий. Достаточно `data`,
`columns` (только `id`, `header`, `accessor`), `rowKey` и `caption`.

```tsx
const columns: TableColumn<Task>[] = [
  { id: 'title', header: 'Задача', accessor: (task) => task.title },
  { id: 'status', header: 'Статус', accessor: (task) => task.status },
  { id: 'assignee', header: 'Исполнитель', accessor: (task) => task.assignee },
];

<Table<Task> data={tasks} columns={columns} rowKey={(task) => task.id} caption="Задачи" />;
```

## Кейс: сортировка

Сортировка включается per-колонка через `sortable`. Тип сравнения — `sortType`
(`'string'` — алфавитный порядок в ru-локали, `'number'`, `'date'`, `'boolean'`),
значение берётся из `accessor`.

```tsx
const columns: TableColumn<Task>[] = [
  { id: 'id', header: 'ID', accessor: (task) => task.numId, sortable: true, sortType: 'number' },
  { id: 'title', header: 'Задача', accessor: (task) => task.title, sortable: true },
  { id: 'due', header: 'Срок', accessor: (task) => task.due, sortable: true, sortType: 'date' },
];

// uncontrolled: начальное направление — defaultSort
<Table<Task>
  data={tasks}
  columns={columns}
  rowKey={(task) => task.id}
  caption="Задачи"
  defaultSort={{ columnId: 'due', direction: 'asc' }}
/>;
```

Клик по заголовку циклит: по возрастанию → по убыванию → сброс (исходный порядок `data`).
Режимы: **uncontrolled** (`defaultSort` + `onSortChange`) и **controlled** (`sort` + `onSortChange`,
когда порядок живёт в URL или стейте страницы). Мультисорт не поддерживается — при нескольких
колонках сортировку собирают снаружи и передают готовый `data`.

Нестандартный порядок (enum-статусы, ранги, сложные ключи) задаётся своим компаратором `sortCompare` —
он получает строки целиком и перекрывает `sortType`:

```tsx
const priorityRank = { Высокий: 0, Средний: 1, Низкий: 2 };

{
  id: 'priority',
  header: 'Приоритет',
  accessor: (task) => task.priority,
  sortable: true,
  sortCompare: (a, b) => priorityRank[a.priority] - priorityRank[b.priority],
}
```

## Кейс: выбор строк

Проп `selectable` добавляет чекбокс-колонку и «выбрать все» в шапке. `selectedIds` — массив
ключей из `rowKey` (не индексов). Выбранные строки подсвечиваются и помечаются `aria-selected`,
при частичном выборе шапочный чекбокс показывает промежуточное состояние.

```tsx
// uncontrolled — начальный выбор
<Table<Task>
  data={tasks}
  columns={columns}
  rowKey={(task) => task.id}
  caption="Задачи"
  selectable
  defaultSelectedIds={['PL-42']}
/>;

// controlled — выбор живёт в стейте страницы
<Table<Task> selectable selectedIds={selected} onSelectedIdsChange={setSelected} ... />;
```

## Кейс: действия над строкой

Проп `actions` добавляет колонку `···` с меню (атом `Dropdown`: Enter/стрелки открывают и ходят,
Escape закрывает и возвращает фокус). Список пунктов может зависеть от строки — передайте функцию.

```tsx
const actions: TableAction<Task>[] = [
  { label: 'Редактировать', icon: Pencil, onSelect: (task) => openEditor(task) },
  { label: 'Удалить', icon: Trash2, danger: true, onSelect: (task) => remove(task) },
];

// разный набор для разных строк
<Table<Task>
  actions={(task) => (task.done ? [restoreAction] : [editAction, deleteAction])}
  actionLabel="Действия с задачей" // имя кнопки-триггера для скринридеров
  ... />;
```

## Кейс: управление колонками

Атом может сам показывать/скрывать колонки и менять их порядок. Всё включается одним пропом
`showColumnSettings`. В шапке колонки действий появляется шестерёнка, по которой открывается
выпадающее меню:

- слева от каждой строки — drag-ручка (шесть точек) для изменения порядка мышью или клавишами;
- справа — `Switch`, который включает/выключает видимость колонки;
- последняя оставшаяся видимая колонка автоматически блокируется, чтобы таблицу нельзя было
  оставить совсем без колонок.

### Включение и начальное состояние

Минимальный вариант — uncontrolled: атом сам хранит состояние между рендерами.

```tsx
<Table<Task>
  data={tasks}
  columns={columns}
  rowKey={(task) => task.id}
  caption="Задачи"
  showColumnSettings
  defaultHiddenColumnIds={['updated']}
  defaultColumnOrder={['id', 'title', 'status', 'priority', 'assignee', 'due', 'updated']}
/>
```

- `defaultHiddenColumnIds` — id колонок, которые будут скрыты при первом рендере.
- `defaultColumnOrder` — начальный порядок data-колонок. Если не передан, используется порядок
  массива `columns`.
- `columnSettingsLabel` позволяет переопределить имя кнопки-шестерёнки для скринридеров
  (по умолчанию — «Настроить колонки»).

### Controlled-режим

Если положение и видимость колонок нужно хранить в URL, на бэкенде или в другом стейте, используйте
controlled-пропсы:

```tsx
const [hidden, setHidden] = useState<string[]>(['updated']);
const [order, setOrder] = useState<string[]>([
  'id',
  'title',
  'status',
  'priority',
  'assignee',
  'due',
  'updated',
]);

<Table<Task>
  data={tasks}
  columns={columns}
  rowKey={(task) => task.id}
  caption="Задачи"
  showColumnSettings
  hiddenColumnIds={hidden}
  onHiddenColumnIdsChange={setHidden}
  columnOrder={order}
  onColumnOrderChange={setOrder}
/>;
```

- `hiddenColumnIds` + `onHiddenColumnIdsChange` — полный контроль видимости.
- `columnOrder` + `onColumnOrderChange` — полный контроль порядка.

### Как работает порядок

- `columnOrder` влияет **только на data-колонки** из пропа `columns`.
- Служебные колонки (`selectable` и `actions` / настройки) всегда остаются на своих местах: чекбокс
  — первая, действия/настройки — последняя.
- Колонки, чьи id есть в `columns`, но отсутствуют в `columnOrder`, дописываются в конец в том
  порядке, в котором они идут в `columns`.
- Переупорядочивание в меню меняет `columnOrder`, при этом скрытые колонки тоже меняют позицию:
  когда их снова включат, они встанут на новое место.

### Drag-and-drop

Reorder работает через `@dnd-kit/sortable`:

- мышью — зажать drag-ручку и перетащить пункт вверх/вниз;
- клавиатурой — сфокусироваться на ручке и использовать `Space` для поднятия элемента, стрелки
  вверх/вниз для перемещения, `Enter` или `Space` для отпускания.

### Ширина и заполнение пустого пространства

Если все видимые колонки имеют фиксированную ширину (`width: number`) и их сумма меньше ширины
контейнера, последняя видимая data-колонка автоматически растягивается через `minmax(<width>px, 1fr)`.
Это гарантирует, что внутри рамки таблицы не останется пустого места справа.

Если среди видимых колонок есть хотя бы одна «резиновая» (`width` не задан или задан через `fr`/
`auto`), растяжение не применяется — сетка и так заполнит контейнер.

### Ограничения

- Настройки работают только для data-колонок из пропа `columns`; колонку выбора строк и колонку
  действий/настроек переместить нельзя.
- Если `actions` не передан, но включен `showColumnSettings`, атом автоматически добавляет пустую
  колонку действий шириной `48px` и помещает в её шапку шестерёнку.

Откройте шестерёнку в правом верхнем углу таблицы: можно скрыть/показать колонки и перетащить
drag-ручки, чтобы изменить порядок.

## Кейс: состояния empty и loading

- `empty` — контент строки, когда `data` пуст: обычно иллюстрация, пояснение и кнопка «Сбросить фильтры».
- `loading` — скелетон-строки вместо данных. Весь интерактив шапки (сортировка, выбор, ресайз)
  отключён, у таблицы `aria-busy`. Ховера у скелетонов и пустого состояния нет.

```tsx
<Table<Task> data={filtered} columns={columns} rowKey={rowKey} caption="Задачи"
  empty={<EmptyState onReset={resetFilters} />} />

<Table<Task> data={tasks} columns={columns} rowKey={rowKey} caption="Задачи" loading />;
```

## Кейс: ширина, выравнивание и переполнение

- Начальная ширина — `width`: px-число или grid-трек (`'200px'`, `'minmax(0,2fr)'`);
  без неё колонка резиновая `minmax(160px, 1fr)`.
- `align: 'right' | 'center'` — выравнивание содержимого (по умолчанию `left`).
- Пользователь меняет ширину драгом за правый край заголовка (минимум 64 px).
- Если сумма ширин не влезает в контейнер — появляется горизонтальный скролл,
  таблица фокусируется и скроллится с клавиатуры. Не сжимайте таблицу внешними стилями.

```tsx
const columns: TableColumn<Task>[] = [
  { id: 'id', header: 'ID', accessor: (task) => task.numId, width: 90 },
  { id: 'title', header: 'Задача', accessor: (task) => task.title },
  {
    id: 'due',
    header: 'Срок',
    accessor: (task) => task.due,
    sortable: true,
    sortType: 'date',
    align: 'right',
  },
];
```

## Кейс: TableRow вне таблицы

`TableRow` экспортирован отдельно — та же сетка и подсветка. Вне `Table` ей нужен шаблон
колонок (`gridTemplateColumns`), а проп `presentation` убирает `role="row"`: строка без таблицы
не должна притворяться строкой таблицы.

```tsx
<TableRow presentation gridTemplateColumns="90px minmax(160px, 1fr) 140px" className="h-11">
  <div className="flex items-center px-3">PL-42</div>
  {/* ячейки — обычные div, без role="cell" */}
</TableRow>
```

## Доступность

- Таблица помечена `role="table"`, заголовки — `role="columnheader"` с `aria-sort`.
- Сортировка и «выбрать все» — настоящие кнопки/чекбоксы, доступны с клавиатуры.
- При `loading` интерактив отключён нативными `disabled`, скелетоны скрыты от скринридеров (`aria-hidden`), у таблицы `aria-busy`.
- Переполненная таблица фокусируется (`tabIndex={0}`) и скроллится с клавиатуры.
- Меню настроек колонок доступно с клавиатуры: переключатели видимости и reorder пунктов
  клавишами (DnD через `@dnd-kit/sortable`).
- Панель axe в Storybook показывает 0 нарушений для всех историй.

## Антипаттерны

- ❌ Передавать колонки без `id` или с нестабильными id — сломается сортировка и ресайз.
- ❌ Хранить выбранные строки по индексу — при сортировке выбор «поедет». Только `rowKey`.
- ❌ Пихать фильтрацию внутрь атома — она специфична для страницы, не для таблицы.
- ❌ Отключать `truncate` ради длинного текста — ломается сетка. Раскрывайте по клику.
- ❌ Несколько интерактивных элементов в одной ячейке — если действий больше одного, используйте колонку действий.
