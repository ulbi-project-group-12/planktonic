# UL-145 Тест-кейсы доступа к пространству

Для каждого кейса вызываем `AccessService.can(user, permission, scope)` и сверяем результат с таблицей. Если в строке перечислены несколько ролей или вариантов цели, проверяем каждый отдельно. Если не указано иное, пользователь активен, а его роль относится к проверяемому пространству.

Источник правил — [ADR-0002, §0 и §2](adr/0002-permission-model.md).

## Действия участника

| Разрешение                     | `OWNER`                      | `ADMIN`                               | `MEMBER` |
| ------------------------------ | ---------------------------- | ------------------------------------- | -------- |
| `workspace.read`               | Да                           | Да                                    | Да       |
| `workspace.update`             | Да                           | Да                                    | Нет      |
| `workspace.member.list`        | Да                           | Да                                    | Да       |
| `workspace.member.remove`      | Цель `ADMIN` или `MEMBER`    | Цель `MEMBER`                         | Нет      |
| `workspace.member.role.change` | Переход `ADMIN` ↔ `MEMBER`   | Нет                                   | Нет      |
| `workspace.ownership.transfer` | Действующему участнику       | Нет                                   | Нет      |
| `workspace.leave`              | После передачи владения      | Да                                    | Да       |
| `workspace.invite.create`      | На роль `ADMIN` или `MEMBER` | На роль `MEMBER`                      | Нет      |
| `workspace.invite.list`        | Все активные приглашения     | Активные приглашения на роль `MEMBER` | Нет      |
| `workspace.invite.revoke`      | На роль `ADMIN` или `MEMBER` | На роль `MEMBER`                      | Нет      |
| `project.create`               | Да                           | Да                                    | Нет      |

## Кейсы, в которых важна цель действия

| Действие                                                    | Кто             | Цель или состояние                                          | Ожидаем |
| ----------------------------------------------------------- | --------------- | ----------------------------------------------------------- | ------- |
| Удалить участника                                           | `OWNER`         | `ADMIN` или `MEMBER`                                        | `true`  |
| Удалить участника                                           | `OWNER`         | `OWNER`                                                     | `false` |
| Удалить участника                                           | `ADMIN`         | `MEMBER`                                                    | `true`  |
| Удалить участника                                           | `ADMIN`         | `ADMIN` или `OWNER`                                         | `false` |
| Изменить роль                                               | `OWNER`         | `ADMIN` → `MEMBER` или `MEMBER` → `ADMIN`                   | `true`  |
| Изменить роль                                               | `OWNER`         | Назначить или снять `OWNER` этим действием                  | `false` |
| Передать владение                                           | `OWNER`         | Действующий участник пространства                           | `true`  |
| Передать владение                                           | `OWNER`         | Пользователь вне пространства или деактивированный участник | `false` |
| Выйти                                                       | Текущий `OWNER` | Всё ещё владеет пространством                               | `false` |
| Выйти                                                       | Бывший `OWNER`  | Передал владение и теперь `ADMIN`                           | `true`  |
| Создать, увидеть в активном списке или отозвать приглашение | `ADMIN`         | Приглашение на роль `MEMBER`                                | `true`  |
| Создать, увидеть в активном списке или отозвать приглашение | `ADMIN`         | Приглашение на роль `ADMIN`                                 | `false` |

Например, для отзыва приглашения берём одного и того же администратора, одно пространство и разрешение `workspace.invite.revoke`. Меняем только роль в приглашении. На `MEMBER` ожидаем `true`, на `ADMIN` — `false`. Роль администратора берётся из его членства, а роль приглашения относится к цели действия.

## Кейсы вне матрицы ролей

| Сценарий                                                                                                        | Ожидаем                       |
| --------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| Активный пользователь без членства запрашивает `workspace.read`                                                 | `false`                       |
| Пользователь владеет другим пространством и запрашивает `workspace.read` для пространства, в котором не состоит | `false`                       |
| Активный аутентифицированный пользователь без членства вызывает `workspace.create`                              | `true`                        |
| Активный аутентифицированный пользователь принимает действительное приглашение без привязки к email             | `true`                        |
| Пользователь принимает действительное адресное приглашение с совпадающим подтверждённым email                   | `true`                        |
| Email не совпадает или не подтверждён                                                                           | `false`                       |
| Приглашение отозвано, просрочено или уже погашено                                                               | `false` для нового вступления |
| Деактивированный `OWNER` запрашивает `workspace.read`                                                           | `false`                       |
| Деактивированный пользователь пытается создать пространство или принять действительное приглашение              | `false`                       |
| Активный `OWNER` запрашивает неизвестное разрешение                                                             | `false`                       |

## Связь с HTTP

В тестах сервиса проверяем `true` и `false`. В тестах HTTP проверяем результат на уровне маршрута. Для видимого пространства без права на действие ожидаем `403`. Для открытия чужого пространства ожидаем `404`.
