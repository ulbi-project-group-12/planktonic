# UL-137. Zod и OpenAPI 3.0

`pnpm openapi:export` из корня репозитория записывает `apps/api/dist/openapi.json`. Чтобы указать другой путь, передайте его первым аргументом, например `pnpm openapi:export ./openapi.json`.

Команда генерирует типы Prisma для сборки API и собирает workspace-зависимости. Для генерации типов и экспорта запущенные PostgreSQL и Redis, `DATABASE_URL` и `REDIS_URL` не нужны. Экспорт сканирует контроллеры health и тестового POST, используя те же декораторы и функцию генерации, что Swagger UI. У UI есть доступ и к другим маршрутам основного приложения.

## Проверенные преобразования

Результаты для Zod 4.6.7 с `target: 'openapi-3.0'`. Тела запросов используют `io: 'input'`, ответы — `io: 'output'`.

| Схема                                                         | Результат и ограничение                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `z.date()`                                                    | В обоих режимах выбрасывает `Date cannot be represented in JSON Schema`. В JSON-контрактах используем `z.iso.date()` или `z.iso.datetime()`. Они дают `type: string`, форматы `date` и `date-time` соответственно, а также `pattern`. Преобразование строки в объект `Date` выполняется отдельно от JSON-контракта. |
| `z.union([z.string(), z.number()])`                           | В обоих режимах даёт `anyOf` со схемами строки и числа. Схема описывает допустимые значения. Порядок попыток Zod и результат преобразований отдельных веток проверяются на стороне приложения. Генерацию типов и моков для объединений нужно проверить в UL-138.                                                    |
| `z.object({ name: z.string(), note: z.string().optional() })` | В обоих режимах `note` есть в `properties`, а `required` содержит только `name`. `optional()` разрешает отсутствие поля. Значение `null` требует отдельного разрешения в контракте. Для обычного `z.object` преобразование ответа также добавляет `additionalProperties: false`.                                    |

## Валидация запросов

Тикет предлагает собственный `ZodValidationPipe`. В текущем Nest 12 уже используется `StandardSchemaValidationPipe`: Zod 4 реализует Standard Schema, а `@Body({ schema })` передаёт схему встроенному пайпу. Существующая фабрика ошибок формирует HTTP 400 с `statusCode`, `message` и массивом `issues` из пар `path` и `message`. Тест POST проверяет этот ответ по контракту. Предложение для ревью UL-137 — сохранить встроенный пайп.

## Установка зависимостей

`@nestjs/swagger` подтягивает `swagger-ui-dist`, а тот — `@scarf/scarf` с install-скриптом. pnpm в этом репозитории прерывает установку при незадекларированном скрипте (`ERR_PNPM_IGNORED_BUILDS`). Запись `'@scarf/scarf': false` в существующем `allowBuilds` явно отключает скрипт. Для Swagger UI и экспорта он не нужен.
