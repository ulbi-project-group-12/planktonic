## Phase Goal

ROADMAP Goal: see 01-01-PLAN.md (verbatim quote and MVP note). This plan adds the rename-proofing the lead required in D-33..D-36. The product name lives in one file, and a guard keeps it out of every other tracked file. Plan 01-07 runs the guard as the required CI check `name-guard`.

<objective>
Create the single source of the product name, `packages/config/product.ts` (D-33). Add a zero-dependency guard, `scripts/check-product-name.mjs` (D-35). It reads the name from that file and fails when the name, in any letter case, appears in a tracked file outside a fixed allowlist. A `node:test` suite proves the guard fails on planted literals and passes on clean trees. Root scripts: `check:name` and `test:root`.

Purpose: "ulbigram" is a working name, and a later `/gsd-quick` rename must touch one place (D-33, D-36). The guard sits early in the phase, so every later plan (apps, workflows, rules, docs) is checked against it.
Output: `packages/config/product.ts` exported as `@app/config/product`, the guard + its test, and root scripts `check:name` and `test:root`.
</objective>

Create `scripts/check-product-name.mjs`. It uses only `node:` built-ins and follows the style of `scripts/check-pins.mjs`. Behaviour:
- Root: `--root <dir>`; default is the repo root resolved from the script's own location.
- Read the source: dynamic `import()` of `<root>/packages/config/product.ts` via `pathToFileURL`. If the file is missing, an export is missing, a term is shorter than 3 characters, or the slug does not match lowercase letters, digits and hyphens, print a clear error and exit 2 (fail closed).
- Terms: the lowercase display name and slug, deduplicated.
- Files: `git -C <root> ls-files -z` via `execFileSync`. Only tracked files are scanned.
- Allowlist: the exact paths `packages/config/product.ts`, `README.md`, `.claude/CLAUDE.md` and `pnpm-lock.yaml`, plus everything under the prefix `.planning/`. CONTRIBUTING.md is deliberately NOT allowlisted; it must avoid the literal.
- Scanning: skip files that contain a NUL byte (binary). Compare each line lowercased against every term.
- Hits: print each to stderr as `<path>:<line>: product name literal, import it from @app/config/product or read PRODUCT_NAME`, then a final count line, and exit 1.
- Clean: print `check-product-name: N tracked files clean` to stdout and exit 0.
- Never print the term itself in the summary line.

Add root scripts `check:name` = `node scripts/check-product-name.mjs` and `test:root` = `node --test --test-reporter=tap scripts/check-product-name.test.mjs`. The TAP reporter gives stable `# pass N` / `# fail N` summary lines on every Node version. The test file arrives in Task 2; `test:root` is first run there.

Run `pnpm check:name` on the real tree. If it reports hits in earlier plans' files, fix those files: rephrase as "this project", or derive the value. Never extend the allowlist.
