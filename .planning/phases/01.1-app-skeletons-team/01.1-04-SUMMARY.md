## Accomplishments

- **Config (D-13):**
  - `envSchema` sets `NODE_ENV` (development, test or production; default development) and `API_PORT` (an integer from 1 to 65535; default 3001).
  - `validateEnv` throws `Invalid environment: <path>: <zod message>; …`, which never carries the received value.
  - `ConfigModule.forRoot` is global and cached, and reads `['.env', '../../.env']`. It ignores env files under `NODE_ENV` `test` or `production`.
- **Bootstrap:**
  - `configureApp` sets the global prefix `api` and turns on shutdown hooks.
  - `main.ts` reads `API_PORT` through `ConfigService<Env, true>` with `{ infer: true }`.
  - A startup failure prints `api failed to start: <message>` and sets `process.exitCode = 1`.
- **Health (D-12 liveness):** `HealthController` (`@Controller('health')`, `@Get()` + `@HealthCheck()`) calls `HealthService.live()`, which returns `HealthCheckService.check([])`. That gives `{"status":"ok","info":{},"error":{},"details":{}}`, so the extra `app` indicator the plan allowed for was not needed.
- **Tests (D-15):**
  - `vitest.config.ts` uses `swc.vite({ module: { type: 'es6' } })` and includes `src/**/*.spec.ts` and `test/**/*.e2e-spec.ts`.
  - There are 9 specs: 7 for env, 1 for HealthService (built through `Test.createTestingModule` with TerminusModule), and 1 for HealthController (with a stubbed service).
- **Image (D-16):**
  - The `build` stage installs pnpm 12.15.0 through npm, copies the root manifests, `packages/` and `apps/`, and runs `pnpm install --frozen-lockfile --ignore-pnpmfile --filter "@app/api..."`, then `build`, then `deploy --prod /out`.
  - The `runtime` stage keeps the `APP_VERSION`/`PRODUCT_NAME` args, copies `/out` root-owned, runs as `USER node`, exposes 3001 and starts with `CMD node dist/main.js`.
  - `/app` holds `dist`, `node_modules` (production only: @nestjs/*, reflect-metadata, rxjs, zod), `package.json`, `README.md`, and the deploy's `pnpm-lock.yaml`/`pnpm-workspace.yaml`.
- **`.dockerignore`:** an allow-list (`**`, then the root manifests, `packages/**` and `apps/**`). It re-excludes build output and local state, and `**/.env*` is the last line.
- **`.env.example`:** a new `--- API (apps/api) ---` group with `API_PORT=3001`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Empty env values count as unset**
- **Found during:** Task 1
- **Issue:** `.env.example` ships `NODE_ENV=` (empty means "each tool's default"). A developer `.env` copied from it would fail the enum during `pnpm dev`.
- **Fix:** both schema fields run through `z.preprocess` (`'' → undefined`) before their defaults. A spec covers it.
- **Files:** apps/api/src/core/config/env.ts, env.spec.ts
- **Commit:** f12fc29, 1e62874

**2. [Rule 1 - Bug] Startup failure path**
- **Found during:** Task 1
- **Issue:** In @nestjs/config 12, `forRoot` is async, so env validation fails inside `NestFactory.create`. By default Nest then logs and calls `process.exit(1)`, and the planned `bootstrap().catch` never ran.
- **Fix:** `NestFactory.create(AppModule, { abortOnError: false })`. Nest's ExceptionHandler still logs the error, which is value-free. The catch then prints `api failed to start: Invalid environment: API_PORT: …` and sets exit code 1.
- **Files:** apps/api/src/main.ts
- **Commit:** f12fc29

**3. [Rule 3 - Blocking, verify environment only] Turbo forces ANSI colour into task output**
- **Found during:** Task 2 verify
- **Issue:** Under `turbo run`, Vitest's summary reads `Tests ␛[22m ␛[1m␛[32m9 passed`. The verify's `grep -Eo 'Tests +[0-9]+ passed'` cannot match it, so `n` came out empty, even with `--no-color` and with output redirected to a file.
- **Fix:** I ran the unchanged verify with `NO_COLOR=1` exported, which Vitest honours over Turbo's forced colour. The result was `rc=0 n=9`. No repo file changed.
- **Note for later plans:** plan 01.1-05 Task 2 (≥ 14 tests) and 01.1-07 (web test counts) use the same grep and need `NO_COLOR=1` too.
