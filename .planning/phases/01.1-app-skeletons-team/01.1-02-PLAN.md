How to choose on the execution day, per line:
- Lines and candidates: pgvector `0.8.<n>-pg18` (the plain Debian-default tag, not `-trixie`/`-bookworm`); redis exact `8.<minor>.<patch>` (plain tag, not `-alpine`/`-trixie`); seaweedfs plain `4.<n>` (not `_large_disk`, `_full` or other suffixes).
- List the candidates with the Docker Hub API, e.g. `curl -sSL 'https://hub.docker.com/v2/repositories/<namespace>/<repo>/tags?page_size=100&name=<prefix>&ordering=last_updated'`. Its `tag_last_pushed` and `digest` fields are the push date and the index digest.
- Take the highest version whose `tag_last_pushed` is at least 14 days old. The choice uses push dates, the stricter of the two dates (e.g. redis 8.10.3 was built 2026-11-05 but pushed 2026-11-07). Task 2's verify backstops it with build dates. Confirm its digest with `docker buildx imagetools inspect <repo>:<tag>` (the `Digest:` line) and its build dates with `docker buildx imagetools inspect --format '{{json .Image}}' <repo>:<tag>@<digest>` (`created` per platform).
- Record a table in the SUMMARY: service, tag, index digest, `tag_last_pushed`, `created` (linux/amd64 and linux/arm64), and whether it is the D-08 tag or a fallback. Add a STATE.md "Blockers/Concerns" item for each fallback: "bump <image> to <D-08 tag> on/after <eligible date>".

Planner evidence (2026-11-12, Docker 29.9.3 / Compose v5.7.0):
- `docker compose up -d --wait` exits 1 as soon as a one-shot service exits, even with status 0. So the ready signal is `docker compose up -d` followed by `docker compose wait s3-init`, which returns the job's exit code (probed: 0 → 0, 3 → 3). `s3-init` therefore depends on all three services being healthy.
- SeaweedFS 4.51 (the fallback), probed in a throwaway container started with `server -s3 -dir=/data -ip.bind=0.0.0.0` and `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` set:
  - `GET /healthz` on the S3 port (8333) answered 200 after 4 s;
  - busybox `wget` exists at `/usr/bin/wget`;
  - `echo 's3.bucket.create -name app-dev' | weed shell -master=localhost:9333` printed `created bucket app-dev`, and `s3.bucket.list` listed it;
  - a second create printed `error: bucket app-dev already exists` and **still exited 0**, so `weed shell`'s exit code does not report command errors;
  - an anonymous `GET /` answered 403 `AccessDenied`, so the AWS_* env identity is in force.
  The same facts are in the master-branch source for 4.52 (`/status`, `/healthz`, `/readyz` routes; AWS_* identity used when no `-s3.config` is given). Task 2's verify re-checks health, bucket and anonymous 403 for whichever version is pinned.
- pgvector `0.8.6-pg18` (the fallback): PostgreSQL 18.6, `vector` extension files present, `PGDATA=/var/lib/postgresql/18/docker`. Postgres 18 images keep data there and declare the volume at `/var/lib/postgresql`. Mount the named volume at `/var/lib/postgresql`, not at `.../data`. redis `8.10.2` ships `redis-cli` (used by the healthcheck).
