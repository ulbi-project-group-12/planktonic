## Phase Goal

See 01.1-01-PLAN.md (verbatim ROADMAP goal, D-01/D-02 scope note, phase map). This plan delivers SC3: `docker compose up` brings up Postgres 18 + pgvector, Redis 8 and SeaweedFS with healthchecks, and an init job creates the bucket.

<objective>
Add the dev-only `compose.yaml` at the repo root (D-08..D-10, UL-8): Postgres 18 + pgvector, Redis 8, SeaweedFS in single-container S3 mode, and a one-shot `s3-init` job, each with a healthcheck, named volumes, loopback-only configurable host ports and dev credentials from env. Extend `.env.example` with the matching dev values.

Purpose: SC3, and the database the api skeleton (plans 01.1-04/05) migrates and checks against. TZ-BE-04/05/13/14.
Output: `compose.yaml`, `docker/postgres/initdb/01-extensions.sql`, `.env.example`.

Planner evidence (2026-11-12, Docker 29.9.3 / Compose v5.7.0):
- `docker compose up -d --wait` exits 1 as soon as a one-shot service exits, even with status 0. So the ready signal is `docker compose up -d` followed by `docker compose wait s3-init`, which returns the job's exit code (probed: 0 → 0, 3 → 3). `s3-init` therefore depends on all three services being healthy.
- Index digests (from `docker buildx imagetools inspect`): `pgvector/pgvector:0.8.7-pg18@sha256:c29f30688a9ad961691bdf0ec1650717cc132a5814619d80f80463d6e4c42e47` (amd64, arm64; pushed 2026-10-31), `redis:8.10.3@sha256:1f88291b4c57bdf249f02eb085a8669889b2d2954e91d4de5118a5da6b78dd53` (pushed 2026-11-07), `chrislusf/seaweedfs:4.52@sha256:57877e32bb90073b37dc109b438ba66e84fd5ed9ced5f5c04f56444ef243ce59` (pushed 2026-11-02). Re-read each digest with `docker buildx imagetools inspect <tag>` before committing; if one differs, use the value read and note it.
- SeaweedFS: the S3 gateway serves `GET /healthz` on its S3 port; `weed shell` takes `s3.bucket.list` / `s3.bucket.create -name <b>` against the master on 9333; with no `-s3.config`, the S3 gateway takes its admin identity from `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`.
- Postgres 18 images keep data under `/var/lib/postgresql/18/docker` and declare the volume at `/var/lib/postgresql`. Mount the named volume at `/var/lib/postgresql`, not at `.../data`.
</objective>
