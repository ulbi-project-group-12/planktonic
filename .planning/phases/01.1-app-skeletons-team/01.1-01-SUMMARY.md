**`pnpm check:pins` now accepts pnpm 12's `allowBuilds:` map, but only as bare package names mapped to literal true/false. A scratch probe confirmed pnpm 12.15.0 reads that key and fails closed without it.**

## Accomplishments

- `scripts/check-pins.mjs`: `allowBuilds` added to `ALLOWED_KEYS`. A new validated block rejects:
  - flow style (`must be a block mapping`);

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Task 1 probe depended on a cold pnpm store**
- **Found during:** Task 1 verify
- **Issue:**
  - The verify greps the allowed install's log for `postinstall`.
  - On this machine the pnpm store already had esbuild 0.25.0's build output in its side-effects cache from the planner's probe, so pnpm reused it and printed no `postinstall` line.
  - As a result, the verify failed even though `allowBuilds` worked.
- **Fix:**
  - Ran the allowed install with `pnpm install --config.side-effects-cache=false`, which forces the script to run. Every other step was unchanged.
  - Separately confirmed that `esbuild: false` installs with no script run.
