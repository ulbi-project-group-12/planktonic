## Interpretations and execution rules (orchestrator, 2026-11-12)

- **SC2 "`GET /api/health` returns 200 under docker-compose"** is read as the dev setup: the api runs on the host (`node apps/api/dist/main.js` in 01.1-05 Task 1, `pnpm dev` in 01.1-10/11) against the compose services, and `/api/health` and `/api/health/ready` both return 200. No api or web service is added to `compose.yaml`; 01.1-05 Task 3 asserts the service list. The container run on the compose network in 01.1-05 Task 3 is an extra image check (D-16), not the SC2 evidence.
- **Image age rule:** every compose image and every Dockerfile base image is the newest tag of its line whose digest is at least 14 days old on the execution day, pinned by digest. 01.1-02 Task 2 and 01.1-04 Task 3 check this mechanically (`docker buildx imagetools inspect` build dates), and the SUMMARYs record digest and dates. One exception applies before 2026-11-19: the Node 26.13.0 base digest (api and web images), under Phase 1 D-29. The lead accepted this on 2026-11-12, with a dated re-check in STATE.md.
- **Env rule:** every Prisma CLI and api invocation in verification exports DATABASE_URL, NODE_ENV=test and API_PORT, with values taken from `.env.example`. No executor step reads, prints or creates a developer's `.env`. Code paths that could read one stay closed during execution: `prisma.config.ts` loads the root `.env` only for database commands when DATABASE_URL is unset, and the api skips env files under NODE_ENV test/production.

## Sampling Rate

- **After every task commit:** the task's `<automated>` command (each states its failing direction).
- **After every plan:** `pnpm check:all` (every plan's last task ends with it).
- **Before `/gsd-verify-work`:** fresh-clone README replay (01.1-11 Task 1) green; CI green on the phase PR with all seven checks.
- **Max feedback latency:** 300 seconds (Docker builds and the fresh-clone replay are the slow ones).
