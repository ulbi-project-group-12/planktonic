## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `next dev` writes `apps/web/AGENTS.md` under an AI coding agent**
- **Found during:** Task 1 smoke run
- **Issue:**
  - Next 16.4.3's `generate-agent-files.js` creates or updates `apps/web/AGENTS.md` (a managed "nextjs-agent-rules" block) whenever `next dev` detects an AI coding agent.
  - The new `pnpm dev` therefore leaves an untracked file for every developer who runs it from an agent, which this team does.
  - Prettier's `format:check` also scans untracked files.
- **Fix:** `.gitignore` gains `apps/web/AGENTS.md` with a one-line reason. The copy this run created was removed. Behaviour and config are unchanged.
- **Alternatives for the lead:** commit the file, which is what Next's own note suggests, or set `agentRules: false` in `next.config.ts`.
- **Files:** .gitignore
- **Commit:** 5c39bdf

**2. [Rule 1 - Accuracy] `.env.example` comments claimed readers that do not exist**
- **Found during:** Task 2
- **Issue:** The 01.1-02 comments said `APP_VERSION`, `PRODUCT_NAME` and `PRODUCT_SLUG` are "read by the apps". A `git grep` shows that only the Dockerfiles (build-args → ENV) and release.yml/ci.yml (repo variables) use them, and no app code does.
- **Fix:** each comment now names the real reader or says "reserved", as the plan's "no variable without a reader or a stated future reader" asks.
- **Commit:** cac7dcf
