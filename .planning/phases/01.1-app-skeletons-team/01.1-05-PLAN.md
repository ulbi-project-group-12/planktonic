Decisions taken here (Claude's discretion, D-12/D-14), to record in the SUMMARY:
- Readiness is a separate endpoint, `GET /api/health/ready` (DB `SELECT 1` through Prisma, 503 when down). `GET /api/health` stays liveness. Phase 4 smoke-checks `/api/health` on each replica and may gate traffic on `/ready`.
- First migration: no product table (product models are Phase 3+). `init` holds only `CREATE EXTENSION IF NOT EXISTS vector;`, so databases that never ran the compose init SQL (CI e2e, Phase 4) get the extension too. Planner probe: Prisma 7.10.1 generates a client from a schema with zero models.

How SC2 is read (orchestrator, 2026-11-12; write it into the SUMMARY): "`GET /api/health` returns 200 under docker-compose" means the api process on the host, built from this repo, talks to the compose services. Task 1 proves it with `node apps/api/dist/main.js` against compose Postgres, and plan 01.1-10 proves it again with `pnpm dev`. No api (or web) service is added to `compose.yaml`; the production compose is Phase 4. Task 3's container on the compose network is an extra image check for D-16.

Env rule for every executor step (orchestrator, 2026-11-12):
- Each Prisma CLI or api invocation in this plan has DATABASE_URL (plus NODE_ENV=test and an API_PORT for api runs) exported explicitly. The values come from `.env.example`, read with `envx() { grep -E "^$1=" .env.example | cut -d= -f2-; }`, the helper the verify commands use.
- The executor never reads, prints or creates `.env`.
- Two code paths can read a root `.env`, and both stay closed during execution: `prisma.config.ts` loads it only for database commands (`migrate`, `db`, `studio`) when DATABASE_URL is unset, so `prisma generate` (and so Turbo and CI) never touches it; and the api's ConfigModule skips env files when NODE_ENV is `test` or `production` (set up in 01.1-04).
- Turbo's strict env mode would drop an exported DATABASE_URL, so the `generate` task lists it in `passThroughEnv`.

Planner probes (2026-11-12, Prisma 7.10.1 in a scratch dir): with `datasource.url: process.env.DATABASE_URL`, `prisma generate` succeeds with DATABASE_URL unset; with `env('DATABASE_URL')` it fails (`PrismaConfigEnvError`). The generated files start with `// @ts-nocheck` and `/* eslint-disable */`, and strict `tsc` (the repo base + decorators) passes on code importing `./generated/prisma/client.js`. `prisma` has a `preinstall` script and `@prisma/engines` a `postinstall` (engine download).
