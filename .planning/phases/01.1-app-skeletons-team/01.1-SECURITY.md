## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| npm registry → developer and CI machines | A dependency's install script runs code at install time | Package tarballs, install scripts (4 approved) |
| PR author → workspace, CI, review and check configs | A PR can widen install scripts, weaken a required check or silence the AI review | `pnpm-workspace.yaml`, workflows, ruleset, CODEOWNERS, `.coderabbit.yaml`, app check configs |
| Docker Hub → developer machine and image builds | Base and service images are pulled from public registries | Digest-pinned image layers |
| Host network → dev services and dev servers | Published ports and dev listeners are reachable from wherever they bind | Postgres, Redis, S3, api, `next dev`, Storybook |
| Env and the root env file → api process and Prisma CLI | Configuration enters the app untyped | `DATABASE_URL`, `API_PORT`, `API_HOST`, `NODE_ENV` |
| Repo working tree → Docker build context | Anything in the context can reach an image layer | Allow-listed manifests, `packages/**`, `apps/**`; env files excluded |
| Internet → `/api/health`, `/api/health/ready` | Unauthenticated probes | Constant liveness body; fixed readiness message |
| Build → client bundle | Client imports ship to browsers | Product display name only |
| CodeRabbit GitHub App → repository | A third-party app reads PR diffs and posts reviews | Public code, review comments (never approvals) |
| shadcn registry → repository | Copied third-party source becomes our code | Button, Input, Dialog source |
| Storybook / Next CLIs → telemetry endpoints | The CLIs can send usage data | Disabled |
| Developer shell → dev processes; Turbo cache → CI | Loose env mode on `pnpm dev`; cached outputs replay across runs | Shell env (uncached `dev` only) |
| Public repository → readers | Docs are public | Dev example values only |
