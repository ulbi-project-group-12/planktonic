Facts: Turbo 2 runs tasks in strict env mode, so variables not declared in turbo.json do not reach tasks; `--env-mode=loose` on the CLI lifts that for one run. Docker Compose v2.24+ reads `COMPOSE_ENV_FILES` instead of `.env`, and `COMPOSE_PROJECT_NAME` sets the project; the smoke run uses both, so it never touches a developer's own `.env`, stack or volumes. App dev scripts already exist: `@app/web` `next dev` (port 3000), `@app/api` `prisma generate && nest start --watch` (API_PORT, default 3001).
</context>
