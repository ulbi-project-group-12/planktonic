## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking, verify] The plan's probe does not trigger the cross-import rule in steiger 0.8.1**
- **Found during:** Task 1 verify
- **Issue:** The literal probe (`features/probe-b/index.ts` exporting a const, and `features/probe-a/index.ts` doing `export { probeB as probeA } from '../probe-b'`) made `lint:fsd` fail only on `fsd/no-segmentless-slices`. That gave literal verify `rc=1`, because it failed for a different rule.
- **Root cause:** In steiger-plugin 0.8.1, `extractDependencies()` keeps only `statement.type === "import"`, so `export … from` re-exports are never checked. I tried more variants:
  - an alias `import` from a segment file → `fsd/forbidden-imports` ("Forbidden cross-import from slice \"probe-b\"");
  - a relative `import` from a segment file → reported;
  - a re-export in a slice `index.ts` next to real segments → not reported.
- **Fix (verification only, no repo change):** I ran the same verify with the probe written as an ordinary cross-feature import in a segment:
  - `probe-a/model/value.ts`: `import { probeB } from '../../probe-b'`;
  - each slice has an `index.ts` public API.

  Result: green before, `fsd/forbidden-imports` with the probe (plus `insignificant-slice`), green after removal, ESLint clean, no probe files left (`RC=0`). This meets D-19, "prove it fails on a deliberate cross-feature import".
- **Remaining gap:** A cross-slice re-export in a slice's public API is not caught by 0.8.1. It is logged in `deferred-items.md` and STATE.md: re-run the original probe after bumping to 0.9.0/0.8.2 (from 2026-11-15).

**2. [Rule 1 - Lint] Plugin types resolve to an error type**
- **Found during:** Task 1 (ESLint step of the verify)
- **Issue:** `@feature-sliced/steiger-plugin` 0.8.1's `index.d.ts` imports `@steiger/toolkit`, which the plugin does not declare as a dependency, so it is not installed. Under typed lint, `fsd.configs.recommended` became an error type, which produced `no-unsafe-argument` and `no-unsafe-assignment`.
- **Fix:** `const recommended = fsd.configs.recommended as unknown as Parameters<typeof defineConfig>[0];` with a two-line reason. This uses steiger's own config type, adds no new package and needs no `eslint-disable`.
- **Files:** apps/web/steiger.config.ts
